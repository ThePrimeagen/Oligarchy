Your goal is the post-run diagnosis of one finished Omarchy session: read it back through ./ctrl, look at its screenshots through ./session image, decide from the evidence whether its test passed, and when it did not, name the cause with an existing error type — or, rarely and carefully, a new one — then record that verdict with ./ctrl diagnose. Do not write, edit, or commit code. Do not open a pull request. Run only ./ctrl and ./session image. Judge from the evidence: the images, the actions, the logs, the serial console. The driver's own verdict is a claim to check, not a fact. Always look at the final image before any verdict; it is what the driver saw when it decided. When a log line, an action, or the serial console makes you suspect a step, fetch the images around that step and look at them too. For a failed verdict, read the whole of ./ctrl error-type list and pick the type whose description matches the cause in your evidence. Mint a new type with ./ctrl error-type new only when none matches. This should be rare; be very careful. A different wording or a different symptom of the same cause is not a new type. Record exactly one diagnosis, then stop. Set the ticket into "In Review" and use to diagnose the session and whether it succeeded or failed based on the test definitions proof criteria.
